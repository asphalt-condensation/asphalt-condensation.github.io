# Content Model

## Overview

The site separates structured app identity from localized prose. App manifests answer "what exists?" Pages answer "what do we say in this locale and at this route?"

Astro validates individual fields through `src/content.config.ts`. `scripts/validate-content.mjs` validates relationships between files.

## App manifest

Location: `src/data/apps/<slug>.json`

| Field           | Type               | Meaning                                                     |
| --------------- | ------------------ | ----------------------------------------------------------- |
| `slug`          | string             | Stable lowercase identifier used in URLs and filenames      |
| `name`          | string             | Default-locale display name                                 |
| `summary`       | string             | Default-locale one-sentence support summary                 |
| `localized`     | object             | Name and summary keyed by every declared locale             |
| `platform`      | string array       | Supported Apple platforms from the schema enum              |
| `status`        | enum               | `available`, `coming-soon`, or `retired`                    |
| `icon`          | root-relative path | Owned icon under `public/apps/<slug>/`                      |
| `accent`        | hex color          | Restrained app identity accent; not a whole-page theme      |
| `defaultLocale` | string             | Locale omitted from public URLs                             |
| `locales`       | object array       | Ordered locale code and human-readable language label       |
| `issueUrl`      | URL                | Shared repository Issue Form chooser                        |
| `repositoryUrl` | URL                | Shared support repository                                   |
| `collectsData`  | boolean            | High-level validation flag, not a substitute for the policy |

### Slug rules

Use lowercase ASCII letters, numbers, and single hyphens. Never reuse a retired app's slug for a different product. Changing a slug changes App Store URLs and therefore requires a redirect and migration plan.

### Status rules

- `coming-soon`: support pages may be public before store release.
- `available`: the app is publicly downloadable and support facts must match the released version.
- `retired`: the app is no longer maintained. Preserve its policy and support history; add a retirement notice rather than deleting routes.

### `collectsData`

This flag gives validation a coarse consistency check. A value of `false` requires every privacy page to explicitly state that the app does not collect data. A value of `true` does not describe what is collected; the policy must enumerate categories, purposes, recipients, retention, deletion, and applicable choices based on verified behavior.

## Page document

Location: `src/content/pages/<app>/<locale>/<kind>.md`

Supported kinds are `support` and `privacy`.

| Frontmatter field | Type   | Meaning                                               |
| ----------------- | ------ | ----------------------------------------------------- |
| `app`             | string | Manifest slug                                         |
| `locale`          | string | Declared locale code                                  |
| `kind`            | enum   | `support` or `privacy`                                |
| `route`           | string | Stable URL without leading or trailing slash          |
| `title`           | string | Browser/content title for this locale                 |
| `description`     | string | Search and share metadata summary                     |
| `languageLabel`   | string | Human-readable language name                          |
| `lastUpdated`     | date   | Date this page's content was last materially reviewed |

Markdown bodies start below the frontmatter. The shared app header supplies the only page-level `h1`, so body sections start at `##`.

## Route invariants

For app slug `example` with default locale `en`:

| Page            | Route field               | Public URL                  |
| --------------- | ------------------------- | --------------------------- |
| English support | `example`                 | `/example/`                 |
| English privacy | `example/privacy`         | `/example/privacy/`         |
| Chinese support | `example/zh-hans`         | `/example/zh-hans/`         |
| Chinese privacy | `example/zh-hans/privacy` | `/example/zh-hans/privacy/` |

Trailing slashes are generated by Astro and are part of the canonical URL contract.

## Cross-file validation

The content validator rejects:

- duplicate app slugs or routes;
- manifest filenames that do not match the slug;
- missing default locales or localized app identity;
- missing owned icon files;
- support/repository URLs pointing away from the shared repository;
- undeclared page locales;
- routes that do not follow the URL contract;
- a missing support or privacy page for any declared locale;
- unresolved `TODO`, `TBD`, `FIXME`, or named placeholders;
- public email addresses in rendered source and Issue Forms;
- no-data privacy pages that omit the required statement;
- support pages that do not explain the GitHub channel.

## Extending the schema

Add a field only when it represents a stable concept used by more than one page or app. Update all of the following in one change:

1. `src/content.config.ts`
2. Existing manifests or pages
3. `scripts/validate-content.mjs` if a cross-file invariant applies
4. `docs/CONTENT_MODEL.md`
5. The scaffold script if new apps need the field
6. Browser tests if the field affects rendering

Do not hide app-specific free-form notes in the public manifest. Put operational context in `docs/apps/<slug>.md` and keep sensitive details out of this public repository.
